# DeepSeek Balance / Usage Viewer (Windows desktop app)

<p align="center"><img src="app_icon.png" width="120" alt="icon"></p>

A lightweight Windows desktop program for viewing your **DeepSeek open-platform account balance and usage**.
The core functionality is implemented purely with the Python standard library (tkinter + urllib + configparser + ctypes/DPAPI).
The "system tray" and "screenshot" features require `pystray` + `Pillow` (bundled automatically into the exe when packaged; for script mode just `pip install pystray pillow`).
The API Key is encrypted with Windows DPAPI and stored locally — never in plain text, never uploaded.

> **Unofficial project**: This project is not affiliated with DeepSeek (DeepSeek Inc.). It only calls the public
> `GET /user/balance` endpoint to read your own account balance. Use at your own risk.

## 0. Security & Privacy (important)

- **API Key never enters the repository**: at runtime, `config.ini` and `history.json` are written to
  `%APPDATA%\DeepSeekBalanceViewer\` — **not in the project directory** — and are excluded in `.gitignore`.
- **Key is encrypted on disk**: on Windows it is encrypted with DPAPI (`CryptProtectData`, bound to the current user);
  on non-Windows it falls back to light obfuscation (the `obf:` prefix). The full Key is never echoed in the UI or logs.
- The program issues only one request: `GET https://api.deepseek.com/user/balance` — read-only, it never changes account state.
- "Today / this-month usage" is a **local sampling estimate** (DeepSeek has not opened a usage endpoint): while the program runs it observes the balance dropping and accumulates the drop as usage; a top-up raises the balance and is not counted as usage.
  History is stored locally only, in `history.json`, and can be deleted at any time.
- If you submit your own changes: **do not** commit `config.ini` / `history.json` / any screenshots.

## 2. Dependencies & Environment

- **Python 3.8+** (install from python.org, check *Add Python to PATH*, and make sure tkinter is included — the official installer includes it by default).
- The **core features require no `pip install`** at runtime (tkinter, urllib, configparser, ctypes are all standard library).
- If you use "system tray" or "screenshot" (both on by default): in script mode you need `pip install pystray pillow`; when packaged, this repo already bundles them into the exe automatically — no extra steps.
  **It still starts without them**: the tray gracefully degrades to "closing the window quits the app", and the screenshot button reports the missing dependency (see `tray.TRAY_AVAILABLE`).
- Only needed when packaging into an `exe`: `pip install pyinstaller`.

## 3. Configuration

### 3.1 Fill in the API Key (required)
1. Open https://platform.deepseek.com and create a new Key under *API Keys*.
2. Run the program (double-click `run.bat` or `python main.py`).
3. Paste the Key in the top "Settings" area → check whether to "Show" it to confirm → click **Save Settings**.
4. The Key is written to the local `config.ini` in encrypted form, and never appears in plain text in the program or logs.

> The endpoint and fields are centralized at the top of `api.py` (`API_BASE_DEFAULT` / `BALANCE_ENDPOINT` /
> `USAGE_ENDPOINT` / timeout & retries). If the official API changes, edit there — no other code needs to change.

### 3.2 Auto-refresh (optional)
- Check "Auto-refresh" and set an interval (seconds, minimum 30); the program silently refreshes in the background at the interval, with no UI stutter.
- Unchecking stops it.

## 4. Running

- **Method 1 (script, recommended for debugging)**: from the command line, enter the directory and run `python main.py`.
- **Method 2 (one-click)**: double-click `run.bat` (prefers `pythonw` to hide the console).
- **Method 3 (single exe)**: see Section 6; after packaging, double-click `DeepSeekBalanceViewer.exe`.

## 5. UI Guide

> **The entire window is self-drawn on Canvas** (fully refactored on 2026-10-25, strictly following `_mockup.html`)
>
> The previous version assembled with ttk differed noticeably from the mockup — ttk cannot produce rounded cards, the top highlight gradient on cards, full-column highlight in the price table, rounded pill badges, or an iOS-style switch. So this refactor hands **all of the main window's visuals** to a single Canvas (`uikit.py::MainView`); PIL is only used to pre-render gradient/rounded bitmaps, and everything else is Canvas primitives. Control styling is 100% code-driven and no longer subject to ttk theme whims.
>
> **Layout is a contract** (all values are mockup CSS px; look at the mockup before changing):
>
> | Block | Position | Height |
> |---|---|---|
> | titlebar | y=0 | 35 |
> | Hero triptych | y=47 | 141 |
> | Model pricing | y=198 | 126 |
> | Balance (last 7 days) | y=334 | 159 |
> | Settings | y=503 | 137 |
> | Status bar | y=654 | 22 |
> | **Window** | **560 × 676** | content bottom exactly equals window height |
>
> These coordinates are asserted item-by-item by `test_logic.py::test_ui_layout`; if you skew them the test goes red.
>
> **Scale conversion (the key to staying sharp at high DPI)**: geometry is always × S (S = DPI scale; falls back to uniform shrink when the screen is too small); fonts use `tkfont.Font(size=-round(px*S))` — **a negative tk size is in pixels**, so the physical font height is also = mockup px × S, strictly proportional to geometry.
>
> **Interaction model**: Canvas has no widget tree; when drawing, clickable rectangles are registered into `_regions`. `<Motion>` hit-testing swaps the cursor and only redraws the affected block (no flicker); `<Button-1>` dispatches to the App callback. The only text input needed — the API Key — uses a real `tk.Entry` placed over the rounded box via `place` (it is not a Canvas item, so `delete("all")` will not accidentally remove it).

- **titlebar**: app name + two pill buttons on the right — "Mini window" and "Toggle dark/light". A third pill toggles the **interface language** (Chinese / English).
- **Hero triptych card**: balance / live speed / cumulative usage side by side, with grant and top-up ratio bars pinned to the bottom row of the card.
  - **Cell 1 · Account balance**: 27px large number + period badge ("Off-peak · 50% off" / "Peak · 2× price", where the discount = `10 / PEAK_FACTOR`, derived from the current period in `pricing.py`) + grant badge.
  - **Cell 2 · Live speed**: download (blue) / upload (orange), refreshed **every 1 second** (shares the same network sampler with the mini window, always running), auto-scaling `B/s → KB/s → MB/s → GB/s`; long uptime never shows negative jumps from a 32-bit counter wraparound.
  - **Cell 3 · Cumulative usage**: **today / this-month** interval usage (`history.consumption_between`, counting only the balance drop, excluding top-ups; the baseline is the last snapshot before the interval, with no double-count or miss across day boundaries).
  - **Bottom dual ratio bars**: grant (green gradient) / top-up (blue gradient) as a percentage of total balance + value.
- **Model pricing**: a compact 3-row table — one row per model for the current period (the current column highlighted light blue) + a final row comparing the other period (greyed out, status pill one shade dimmer). The top-right shows live "Off-peak 50% off active · Peak in 2h 14m" (countdown from `pricing.next_period_change()`); **click it** to pop up pricing notes (unit / model versions / concurrency limits / peak rules / price-source snapshot).
  - The single source of truth is `pricing.py::PRICING_OFFPEAK` (off-peak unit price); the peak price is auto-derived per the official rule "off-peak × `PEAK_FACTOR`".
  - Official wording: peak = Beijing time Mon–Fri (excluding statutory holidays) 9:00–12:00, 14:00–18:00; all other times (including weekends and holidays all day) are off-peak. This program **does not auto-detect statutory holidays** and conservatively treats holiday days as peak (display only; does not affect account data).
  - Only two models are on sale: `deepseek-flash` (DeepSeek-V4.1-Flash) and `deepseek-v4-pro` (DeepSeek-V4-Pro-0813). The old names `deepseek-v4-flash`, `deepseek-v4-flash-vision-exp` correspond to models that have been taken offline (still callable but billed as Flash), so they are not listed separately; "image understanding" is a capability of `deepseek-flash`, not a standalone model.
  - If the official price changes, just edit `PRICING_OFFPEAK` and `PRICING_SNAPSHOT` in `pricing.py` (`test_logic.py::test_pricing` is the regression guard and will error if you get it wrong).
- **Balance (last 7 days)**: a daily-sampled area-gradient curve + 7 date axes, with "Avg ¥x.xx/day" in the top-right.
- **Settings (two-column grid)**: API Key (spans) / refresh interval / auto-start (switch) / mini-card shows (5 multi-select chips) / export CSV / about (version number). All **saved instantly** — there is no "Save" button. To change the interface language, use the titlebar language pill.

  (This bar is not in the mockup, but status feedback is a necessary feature, so it is kept as a thin row.)

## 5.1 "📌 Pin to desktop" mini mode (zero-dependency)

Click the "📌 Pin to desktop" button in the settings area; the main window hides and a **borderless, always-on-top** mini floating card pops up, which you can pin to any corner of the desktop:

- **Drag to move**: press and hold the left button anywhere on the card to drag.
- **Double-click to refresh**: immediately refresh balance and period pricing manually.
- **Right-click menu**: "Restore full window" / "Manual refresh" / "Quit". (When the language is switched to English, these menu items are also shown in English.)
- **Configurable display items**: the "Mini card shows" section in settings can check **large balance / current period / billing unit price / cumulative usage / network monitor** (defaults to the first two + network monitor). Checking takes effect **instantly** — if the mini window is open it rebuilds its content immediately, no restart needed; the configuration is written to the `[ui]` section of `config.ini` (`mini_show_balance` / `mini_show_period` / `mini_show_price` / `mini_show_consumption` / `mini_show_net`) and persists across restarts.
- **Live network monitoring**: when checked, the mini card adds a "Network monitor" block, refreshing `↓ download` / `↑ upload` speed **every 1 second**, auto-scaling `B/s → KB/s → MB/s → GB/s` (2 decimal places); long uptime never shows negative jumps from 32-bit counter wraparound.
- **Adaptive window size**: the mini window is no longer a fixed `230x150`; instead it smoothly scales (exponential easing, ~12 frames / 16ms per frame) to the size required by the current content, growing taller/wider as items are checked/unchecked and as speed-text length changes — **text is always shown in full, never clipped or overflowing**. The natural content size is read from `winfo_reqwidth/reqheight`, so per-item height constants are not hand-written.
- Auto-refresh continues in the background; the mini card syncs the current billing price with every refresh.
- The mini card appears in the top-right corner by default to avoid covering the main workspace.

> This mode uses only native tkinter capabilities (`overrideredirect` to remove the border + `wm_attributes("-topmost", True)` to stay on top), introduces no third-party dependencies, and does not affect single-exe packaging.

### Mini card visuals (`uikit.MiniView` fully self-drawn; real glass `[ui] glass` optional)

The mini card container is a **rounded-rectangle card**; by default it uses a solid fill (`MINI_THEMES[*]["card"]`) + a 3px top highlight + 1px inner stroke + a separate semi-transparent shadow layer, with rounded corners cut by `SetWindowRgn` — independent of DWM compositing, **text contrast stays stable on any wallpaper**.

Real liquid glass (live desktop blur showing through) is fully preserved; set `[ui] glass` in `config.ini` to `true` to enable it, with zero third-party dependencies. The recipe references industry implementations (PyPI `py-window-styles`'s tk acrylic, Qt `BlurWindow`), measured on Win11 26300 + Tk 8.6 on 2026-10-25:

> ⚠️ The cost of enabling it is the same as for the main window: `extend_frame(-1)` pulls the entire window into DWM compositing and dilutes the GDI text via the backdrop (`_audit_contrast.py` measured it dropping to 1.5~4.0:1). The main window is therefore off by default, and the mini card likewise. The recipe below is kept as an "optional look" record.

- **Real acrylic (background blur)**: the card face lays down **pure black** as the "glass mask"; `glass.apply_acrylic` calls `SetWindowCompositionAttribute(Attribute=30, AccentState=3, GradientColor=tint)`, and DWM replaces the black pixels with the **live-blurred + tinted** backdrop behind it — showing the real desktop (wallpaper / other windows).
  The recipe is line-for-line consistent with PyPI `py-window-styles` (Akascape)'s "acrylic" style.
  ⚠ `AccentState=4` (ACRYLICBLURBEHIND) has **never shipped on released Windows** — the API returns success but renders nothing, leaving a solid black card; you must use `AccentState=3` (BLURBEHIND).
- **Pull the entire window into DWM compositing**: `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE=20, 1)` + `DwmExtendFrameIntoClientArea(MARGINS(-1,-1,-1,-1))` for a stable backdrop render.
- **⚠ Do not use the `-transparentcolor` color key**: on the local Tk 8.6, setting a color key stops rendering of **all** window content (text, opaque background) — the black-mask route has no such problem and text stays crisp.
- **⚠ `winfo_id()` is not the top-level HWND**: tkinter's Toplevel (especially `overrideredirect`) `winfo_id()` returns a child window handle, and DWM APIs only accept the top-level window (otherwise `err=6 ERROR_INVALID_HANDLE`). `glass.get_toplevel_hwnd()` resolves it via `GetParent` (falling back to `GetAncestor(GA_ROOT)`) before calling.
- **⚠ Timing is critical (measured on Win11 26300)**: dark attribute → accent → extend frame → **region last** — **the window-region change is the reliable trigger that makes DWM render the backdrop** (`SWP_FRAMECHANGED` / `RedrawWindow` do nothing); with only the accent applied the backdrop may not render. Hence `_open_mini` / theme switch both re-issue an `_ensure_glass`, and the autosize easing naturally refreshes the region every frame.
- **Rounded corners**: `glass.set_round_region` uses GDI `CreateRoundRectRgn` + `SetWindowRgn` (`GLASS_RADIUS=16`), converting logical pixels to physical pixels internally via `GetDpiForWindow` — corners stay accurate at high DPI / multi-monitor.
- **Soft shadow**: a separate semi-transparent black window (`mini_shadow`, one ring larger than the card, offset down-right) acts as the shadow layer, moving / scaling / crossing screens with the card (`_sync_shadow`).
- **Semi-transparent layering + edge highlight**: the acrylic tint is controlled by the theme tint (dark `0x292929` 16% dark-grey tint / light `0x40F0F0F0` 25% white tint, values matched to the pywinstyles measured recipe), layered with a top highlight band (`_add_glass_highlight`) + 1px inner stroke (Frame `highlightbackground`). When glass is active, the card face is the black mask color (`MINI_THEMES[*]["mask"]`); text / highlight / stroke are drawn on top in theme colors.
- **Light / dark dual themes**: `MINI_THEMES` has two palettes, defaulting to follow the system `AppsUseLightTheme`; right-click "Toggle dark/light" switches instantly and persists (`mini_theme`, empty = follow system). Three text levels (primary/secondary/weak) and Apple accent colors (download blue / upload orange / idle green / peak red) guarantee high-contrast readability on any background.
  **The light version has been deepened overall** (2026-10-25, contrast on white-tinted glass all ≥ WCAG AA): primary/secondary/weak text `#141A23 / #46505F / #6E7683`, download blue `#0062D6`, upload orange `#C75B00`, idle green `#1E7A38`, peak red `#B3231A`, inner stroke `#B9C0CC`.
- **Solid fill is the default path (not a downgrade)**: when `[ui] glass = false`, the card face is the solid `card` color + rounded corners + highlight + stroke; when acrylic is unavailable (non-Windows / API failure) it automatically falls onto the same path — there is never an "all-transparent invisible card".
- Performance: DWM compositing blur (GPU); corners/shadow are only recomputed on creation, autosize, and theme switch; the network speed only changes text every second and triggers no redraw.

### Main window: solid fill by default; real glass is **optional and known to reduce readability** (corrected 2026-10-25)

⚠️ **This is a correction; do not change it back.** The previous main window defaulted to real acrylic, and the user's real-machine screenshot feedback said "completely unreadable". After quantifying with `_audit_contrast.py`, two real defects were confirmed:

| Defect | Symptom | Quantified |
|---|---|---|
| Canvas background hardcoded `#000000` | title bar / card gaps / status bar all pure black, dark text on black "disappears" | — |
| `AccentState=3(BLURBEHIND)` + `extend_frame(-1)` | DWM re-composites **the entire client area**, blurring the Tk/GDI-drawn text and washing it out with the wallpaper behind | detail-row contrast drops to **1.45:1** (WCAG AA requires 4.5) |

Mechanism: `DwmExtendFrameIntoClientArea(-1)` pulls the whole window into a sheet-of-glass; DWM re-composites the client area as a glass panel, and the GDI text on that composite layer gets diluted by the backdrop (desktop wallpaper).
**This is unrelated to color; you cannot fix it by adjusting the palette** — the user's wallpaper is bright blue-purple, and the dark text is simply washed white.

So the current strategy:

- **Solid fill by default** (`config.ini`'s `[ui] glass = false`): Canvas background = theme window background (`MAIN_THEMES[*]["win_bg"]`), and a window-background rectangle is **explicitly painted full** at render time, not relying on the Canvas's native background. The glass feel is delivered with static techniques: rounded cards + top highlight gradient + 1px stroke + graded over-color (`_mix()` converts the mockup rgba into solid colors). Pixel-level controllable, stable contrast **13:1 ~ 20:1**.
- **System-level details are still retained**: Win11 system rounded corners (`DWMWA_WINDOW_CORNER_PREFERENCE=33, DMWCP_ROUND=2`, keeping snap/scale/shadow, silently degrading to square corners on Win10), and native title-bar dark/light following the theme (`DWMWA_USE_IMMERSIVE_DARK_MODE`).
- **To try real glass**: set `[ui] glass` to `true`. The cost is blurry text (see the table above) — a purely cosmetic trade-off, with no functional impact. `glass.clear_window_glass()` actively undoes the DWM composite state when using solid fill, to avoid leftovers.

### Readability gate (`_audit_contrast.py`, added 2026-10-25)

Turning the subjective "unreadable" into a regressible hard metric, **run automatically after every screenshot**:

- **Text contrast**: WCAG contrast between the "modal color (card background)" of a region and the "0.4% of pixels with the greatest brightness difference from the background (text strokes)" across 7 text-dense regions, threshold `4.5:1`;
- **Sharpness**: Laplacian variance; blurry text is significantly lower.

```bash
python _shot_ui.py            # real default path (solid fill) -> auto-audit after screenshot, should PASS
python _shot_ui.py --glass    # force real glass -> audit should FAIL (negative evidence)
```

Self-check effectiveness: running it on the user's problematic screenshot yields `1.18 ~ 2.42` (FAIL); after the fix it yields `8.2 ~ 20.1` (PASS).

### Network sampling implementation notes (`netmon.py`)

Uses `ctypes` to call Windows IPHelper's `GetIfTable` directly to read the cumulative byte counters of network cards, and differences the two samples to get the rate — **without installing psutil or similar third-party libraries**:

- **Must deduplicate**: the up/down counters of the same physical NIC are duplicated by filtering modules like WFP (`WFP Native` / `WFP Virtual`), `WinpkFilter`, and QoS — measured at about 14 copies for one Wi-Fi card. Summing all rows directly inflates the speed by more than tenfold. So first use `GetAdaptersInfo` to get the **real adapter index set**, and only accumulate the rows corresponding to those indices (filtering modules are not IP adapters and are naturally excluded).
- **Do not rely on `OperStatus == 1`**: an active NIC may actually report `5` (Dormant) instead of `1` (Up); filtering by status bits reads it as 0, showing a permanent `0 B/s`. Switch to filtering by "real index" and you don't need the status bit.
- 32-bit counter wraparound protection: when `cur < prev`, compensate by `2**32` to avoid huge negative rates.
- When sampling fails (non-Windows / interface unavailable) it shows `N/A`, without affecting the balance main feature.
- **Multi-monitor adaptation**: the mini window can be dragged to any monitor (including a secondary screen). When clamping the adaptive size to boundaries, it uses the work area of the **monitor the window is currently on**, obtained via `MonitorFromWindow` + `GetMonitorInfoW`, not `winfo_screenwidth/height` (which on multi-monitor Windows returns only the primary screen and would misjudge a window on the secondary as out of bounds and snap it back). Thus dragging to a secondary screen is not pulled back by the per-second autosize refresh.

## 5.2 System tray / auto-start / data export

- **System tray resident**: closing the main window no longer quits directly, but minimizes to the system tray (bottom-right of the taskbar); the tray icon's right-click menu offers "Show main window / Pin to desktop / Refresh / Quit". The tray icon is drawn live by `Pillow` (green DS), no external image needed.
  If the runtime environment has no desktop (e.g., a server session), the tray automatically degrades: closing the window quits directly, without affecting the main feature.
- **Auto-start**: in "Settings", check "Auto-start (pins the mini card on launch)"; the program writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` and next login automatically starts in **mini-window** mode (with the `--mini` argument). Unchecking removes it.
- **Export CSV**: the "Export CSV" button in the settings area exports the balance history from `history.json` to `balance_history_YYYYMMDD.csv` (with time / currency / total balance / cumulative usage) for monthly reconciliation. The file has a UTF-8 BOM so Excel can open it directly.
- **Screenshot**: the "Screenshot" button uses `Pillow` to capture the currently visible window (preferring the mini window, otherwise the main window) to `balance_snapshot_YYYYMMDD_HHMMSS.png`, for sharing or record-keeping.

> **Built version (2026-10-08)**: `dist/DeepSeekBalanceViewer.exe`, a single file of about 20.4 MB (including tray + screenshot dependencies + `netmon`).
> Packaged with system Python 3.14 + PyInstaller 6.22.3; the extra `pystray` + `Pillow` are auto-collected by hidden-import
> (`netmon` is an ordinary module of this project, imported directly by `ui.py`, so the packager includes it automatically without an explicit declaration).
> Intermediate build products `build-venv/`, `build/`, `build2/`, `build3/`, `dist2/`, `dist3/` can be safely deleted (re-installed / re-generated on repackaging).

>
> ⚠️ **If you change the source, you must repackage, otherwise what you see is still the old exe's behavior**:
> what users double-click daily is `dist/DeepSeekBalanceViewer.exe`, which is **a snapshot at packaging time** and does not follow changes to the `.py` source.
> Typical symptom: you clearly added a new feature in the source and all tests are green, but it "just isn't there" in the UI / mini card.
> How to troubleshoot: compare the modification time of `dist/*.exe` with the latest `.py`; also confirm whether `config.ini` is missing the config key for the new feature
> (the old exe doesn't know the key and naturally won't write it). If both match, it's time to repackage.
> Quick self-proof of whether the new package contains the target modules and is "newer than the source" (no GUI needed):
> ```bat
> build-venv\Scripts\python.exe _check_bundle.py netmon ui tray
> ```
> Output `RESULT: PASS` means the artifact is up to date; `STALE` means the source changed without repackaging.
> For visual evidence see `_shot_netmini.py`: launch the new package → locate the mini window → screenshot (the coordinate-conversion pitfall at 125% DPI on the local machine is noted in that file's comments).
>
> **If repackaging reports "cannot delete old artifact" (PermissionError / trash failure)**, check two things in order:
>
> 1. **Whether the old exe process is still running** (the most common cause): on Windows the exe locks itself while running, so PyInstaller can neither delete nor overwrite it. **After each `timeout`/double-click verification launch, always end the process**:
>    ```bat
>    taskkill /F /IM DeepSeekBalanceViewer.exe
>    ```
>    (Note: in onefile mode there are both a bootstrapper process and a main process; seeing 2 processes is normal.)
> 2. When the directory itself is protected by a security policy (`rm` / `mv` / `shutil.rmtree` may all be blocked), switch to a path that **only creates, never deletes**:
>    ```bat
>    pyinstaller --noconsole --onefile --name DeepSeekBalanceViewer ^
>      --distpath dist2 --workpath build2 --specpath build2 ^
>      --hidden-import tray --hidden-import pystray --hidden-import pystray._win32 ^
>      --hidden-import PIL --hidden-import PIL.Image --hidden-import PIL.ImageDraw ^
>      --hidden-import PIL.ImageGrab main.py
>    ```
>    Then use **write-overwrite** (no delete, no rename) to put the new exe back into `dist/`:
>    ```bat
>    python -c "d=open('dist2/DeepSeekBalanceViewer.exe','rb').read(); open('dist/DeepSeekBalanceViewer.exe','wb').write(d)"
>    ```

## 7. Verification Steps

### 7.1 Normal scenarios
1. Enter a valid Key → save → click "Manual refresh".
2. Expected: the status bar shows "Refresh succeeded", the large balance number appears, and the bars and trend chart update.
3. Check auto-refresh (e.g., 60 seconds), wait a moment, and confirm the UI updates automatically without stutter.
4. **Collapse acceptance**: click the title row of any of "Balance composition" / "Recent usage" / "API price" → the content collapses, the arrow becomes ▸, and the summary still shows on the right; click again to expand. Refresh once and restart the program to confirm the collapsed state is remembered (see the `[ui]` section of `config.ini`).

### 7.4 Mini-window network-monitor acceptance
1. Click "📌 Pin to desktop" → the mini card should show the "Network monitor" block, initially `↓ download -- / ↑ upload --`, and about 1 second later (the first sample needs two time points) become a real rate like `↓ download 16.60 KB/s`.
2. **Value sanity**: at idle it should be close to `0 B/s`, and rise noticeably when opening a web page / downloading a file; if the value is constantly inflated to tens of MB/s, the NIC counters are being double-accumulated (see the deduplication note in `netmon.py`).
3. **Adaptive size**: in settings check/uncheck "Billing unit price" / "Cumulative usage" → the mini window should smoothly grow/shrink in height, with text shown in full, no clipping, no overflow, no abrupt horizontal whitespace change.
4. **Unit carry**: when downloading a large file, watch the unit auto-jump from `KB/s` to `MB/s` (2 decimal places).
5. **Cleanup**: after closing the mini window (right-click "Restore full window" or "Quit"), the network timer should stop; repeated toggling should not leak timers (watch whether CPU usage falls back).
6. **Packaged-version consistency**: confirm the running `dist/*.exe` build time is later than the latest source, otherwise the new feature in the source won't appear (`_check_bundle.py` can decide in one click).

### 7.2 Exception scenarios
| Scenario | Action | Expected prompt |
|----------|--------|----------------|
| No Key configured | Start with Key cleared | Main area shows a "API Key not configured" guide; clicking refresh prompts inability to refresh in the status bar |
| Key invalid/revoked | Enter a wrong Key and refresh | Popup "Invalid API Key" + corresponding status bar info (HTTP 401) |
| Network failure/timeout | Disconnect or set wrong base_url and refresh | Popup "Network Error" + status bar info (includes timeout/connection failure) |
| Rate limited | Refresh frequently to trigger 429 | Popup "Rate Limited" + automatic exponential backoff retry (up to 3 times) |
| Server 5xx | Refresh during official jitter | Popup "Server Error" + backoff retry |
| Usage endpoint not open | Normal refresh | Usage area honestly shows "Official usage endpoint not yet open", no error |

### 7.3 Security self-check
- Open `%APPDATA%\DeepSeekBalanceViewer\config.ini` and confirm `api_key_encrypted` is
  `dpapi:...` or `obf:...` ciphertext, not plain-text `sk-...`.
- Confirm the program makes no outbound requests except to `api.deepseek.com` (check at firewall/proxy).
- Repo self-check: `git ls-files | grep -E "config.ini|history.json|\.png$"` should be empty (only `app_icon.png`).

## 8. Design Notes

- **Why is usage "locally tracked"?** DeepSeek's public API currently only provides `GET /user/balance`,
  with no public "request count / token usage" endpoint. This program reserves `USAGE_ENDPOINT` and the parsing slot in `api.py`,
  ready to enable once the official API opens it; until then it uses the local balance drop as a proxy usage metric, and labels it honestly.
- **Why the standard library?** For zero dependencies, easy packaging, and easy auditing, and because Key encryption uses the system-level DPAPI directly, which is more reliable than rolling your own crypto.
- **No UI stutter**: all network requests run in a background thread, and results update the UI on the main thread via `after()`.
